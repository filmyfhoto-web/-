# รวมตะกร้า 2 ปุ่ม + ขั้นตอน "ยืนยันและแก้ราคา" ฝั่งแอดมิน

## ผลตรวจสอบ (ตรวจจริงจากโค้ด/ฐานข้อมูลแล้ว)

1. **โครงสร้างราคา**
   - `orders` + `order_items` เก็บราคาแยกรายบรรทัดจริง (`order_items.price`, `total`, และ `orders.subtotal/total`) → แอดมินแก้ราคาได้เลย ไม่ต้องเพิ่มคอลัมน์
   - `customer_purchase_orders` และ `school_requisitions` เก็บรายการเป็น `items` (jsonb) + `total` → แก้ราคาได้เช่นกัน แต่ต้องเขียนทับทั้งก้อน jsonb
   - สิทธิ์ตาราง (GRANT) ของ `authenticated` ครบทั้ง 4 ตารางแล้ว และมี policy `staff manage order items` / `staff update orders` → แอดมินแก้ราคาได้โดยไม่ต้องแก้ RLS
   - **ยังไม่มี** ที่เก็บ "ใบเสนอราคาที่สร้างแล้ว" — ต้องเพิ่มคอลัมน์ชุดใหม่ (แบบเดียวกับ `delivery_note_file`)

2. **เทมเพลต PDF ที่ใช้ต่อได้ทันที**
   - `src/lib/pdf.ts` → `makePdf()` รองรับ `kind: "quotation"` ("ใบเสนอราคา / Quotation") อยู่แล้ว ครบทั้งฟอนต์ไทย Sarabun, ตารางรายการ, ยอดรวม/ส่วนลด/VAT → **ใช้อันนี้ ไม่เขียนใหม่**
   - (`src/lib/requisitionPdf.ts` เป็นเทมเพลตใบเบิกเฉพาะทาง ไม่ต้องแตะ)

3. **Excel**
   - `downloadXlsx(filename, { sheet: rows })` รับ array ของ object แบน ๆ → ต่อกับตารางราคาได้ตรง ๆ เหมือนที่ `Shop.tsx` ใช้ ไม่ต้องปรับตัว helper

4. **Cart.tsx**
   - ปุ่มจบตะกร้าตอนนี้มี 2 จุด (ปุ่มในบล็อกสรุป + ปุ่ม sticky ล่างจอ) เรียก `submit()` → `guest-order-submit` เหมือนกัน
   - เพิ่มปุ่มที่สองได้ง่ายที่สุดโดยให้ `submit()` รับพารามิเตอร์ `intent: "order" | "quote"` แล้วส่งต่อไป edge function จุดเดียว

## สิ่งที่จะทำ

### ส่วนที่ 1 — ฝั่งลูกค้า
- `src/pages/Cart.tsx`: ปุ่มจบตะกร้าเหลือ 2 ปุ่มชัดเจน (ทั้งบล็อกสรุปและ sticky)
  - **สั่งซื้อเลย** (ปุ่มหลัก) — พฤติกรรมเดิมทุกอย่าง
  - **ขอใบราคา / ทำใบเบิกไปก่อน** (ปุ่มรอง) — ใช้ flow เดียวกัน แต่ส่ง `doc_intent: "quote"` ข้อความสำเร็จเปลี่ยนเป็น "ส่งคำขอใบราคาแล้ว"
  - ไม่มีช่องกรอกเพิ่ม เงื่อนไข validate เดิมทั้งหมด
- `supabase/functions/guest-order-submit/index.ts`: รับ `doc_intent` (ค่าปริยาย `order`), เขียนลง `orders.doc_intent` + `customer_snapshot.doc_intent` และตั้ง `status = 'pending_quote'` เมื่อเป็น quote
- ตัดออกจากหน้าแรกร้าน: ปุ่ม "ทำใบเขียนเบิก" และปุ่ม "นำเข้า Excel" (จะไล่หา component ที่วางปุ่มนี้จริงตอนลงมือ แล้วเก็บ route เดิมไว้ไม่ให้ลิงก์เก่าพัง)

> **หมายเหตุสำคัญ:** ลูกค้าที่ไม่ล็อกอินเขียน `school_requisitions` ไม่ได้ (ตารางนั้นผูก `user_id`/RLS) ดังนั้น "ใบเบิก" จากตะกร้าจะบันทึกใน `orders` เหมือนเดิม แต่ติดธง `doc_intent='quote'` และหน้าแอดมินแสดงป้าย "ใบเบิก / ขอใบราคา" — ไม่แตะระบบใบเบิกเดิมของแอดมิน

### ส่วนที่ 2 — ฝั่งแอดมิน (งานและเอกสาร)
- **Migration** เพิ่มคอลัมน์ (ทั้ง `orders`, `customer_purchase_orders`, `school_requisitions`):
  `quote_file jsonb`, `quote_sent_at timestamptz`, `quote_sent_by text`, `priced_at timestamptz`, `priced_by text`
  และเพิ่ม `orders.doc_intent text not null default 'order'`
- `src/lib/workDocs.ts`: เพิ่ม
  - `loadWorkItemLines(item)` — อ่านรายการ+ราคาตามชนิดงาน (`order_items` หรือ `items` jsonb)
  - `saveWorkItemPrices(item, lines)` — เขียนราคากลับ + อัปเดตยอดรวม (`orders.subtotal/total` หรือ `total`) + `priced_at/by`
  - `uploadQuoteFile()` / `sendQuote()` — ใช้ bucket และ edge function เดิม
- `src/components/admin/work-docs/PriceEditor.tsx` (ใหม่): ตารางแก้ราคาต่อหน่วย คำนวณยอดอัตโนมัติ + ปุ่ม
  - "ยืนยันราคาและสร้างเอกสารส่งลูกค้า" → `makePdf({ kind: "quotation", ... })` → อัปโหลดเข้า bucket `invoice-attachments` → บันทึก `quote_file`
  - "ดาวน์โหลด Excel" → `downloadXlsx` จากตารางเดียวกัน
- `src/pages/admin/WorkDocs.tsx`: แทรกขั้นตอนใหม่ในแผงรายละเอียด ระหว่าง "ยืนยันรับงาน" กับ "ส่งใบส่งของ"
- `supabase/functions/send-work-doc-notify/index.ts`: รองรับ `action: "quotation"` (ใช้กลไกกันส่งซ้ำ/log เดิม)
- อัปเดตเทสต์ `src/__tests__/work-docs-flow.test.ts` และเพิ่มเทสต์การคำนวณราคา

## จุดที่ต้องระวังเป็นพิเศษ (การคำนวณ/บันทึกราคา)
- **ปัดเศษ**: คิดเป็นทศนิยม 2 ตำแหน่งจุดเดียว (helper `round2` ที่มีอยู่) ทั้งบรรทัด/ยอดรวม/PDF/Excel — ห้ามคำนวณซ้ำคนละที่
- **ยอดรวมต้องมาจากบรรทัดเสมอ** ไม่เชื่อค่า total เดิมในฐานข้อมูล
- **web_order** ต้องอัปเดต `order_items.price/total` และ `orders.subtotal/total` ในคำสั่งเดียวกัน ถ้าอย่างใดล้มให้แจ้ง error และไม่ถือว่ายืนยันราคาแล้ว
- **jsonb items** ต้องเขียนทับทั้งก้อนโดยรักษาฟิลด์อื่นของแต่ละบรรทัดไว้ (ห้ามทิ้ง `unit`, `code`)
- ล็อกการแก้ราคาหลังส่งใบเสนอราคาแล้ว (แก้ได้ต้องกด "แก้ราคาอีกครั้ง" เพื่อกันแก้ทับเงียบ ๆ)
- ราคา 0 อนุญาตได้ แต่เตือนก่อนสร้างเอกสาร

## ความเสี่ยง
- แตะ `guest-order-submit` = เส้นทางสั่งซื้อจริงของลูกค้า → เพิ่มเฉพาะฟิลด์ optional, ค่าปริยายเท่าเดิม
- Migration เพิ่มคอลัมน์อย่างเดียว ไม่แก้ของเดิม → ย้อนกลับง่าย
- PDF ฟอนต์ไทย: ใช้ `makePdf` ที่ผ่านการใช้งานจริงแล้ว ความเสี่ยงต่ำ

## ความซับซ้อน
กลาง–สูง: ~2 ไฟล์ลูกค้า + 4 ไฟล์แอดมิน + 2 edge functions + 1 migration
