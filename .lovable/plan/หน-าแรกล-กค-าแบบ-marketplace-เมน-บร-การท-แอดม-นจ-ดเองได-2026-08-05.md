# หน้าแรกลูกค้าแบบ Marketplace + เมนูบริการที่แอดมินจัดเองได้

## เป้าหมาย
1. ปรับหน้าแรก `/shop` ให้ใกล้ภาพตัวอย่างที่ส่งมามากขึ้น
2. เพิ่มระบบให้แอดมินจัดการ "เมนูบริการ" ได้เอง: ลากสลับตำแหน่ง, ซ่อน/แสดง, เพิ่ม/แก้ชื่อ, อัปโหลดรูปไอคอนเอง — บันทึกลงฐานข้อมูล ลูกค้าทุกคนเห็นเหมือนกัน

## ส่วนที่ 1 — ปรับหน้าตาหน้าแรก
- แถบค้นหา: ช่องใหญ่ขึ้น มุมโค้งเต็ม (pill) ไอคอนแว่นขยายซ้าย ไอคอนกล้อง/สแกนขวา ถัดมาเป็นตะกร้าและแจ้งเตือนพร้อม badge ตัวเลข
- การ์ดร้าน: โลโก้กลมซ้าย ชื่อ "นัฐภรณ์ เชียงกลาง" ตัวหนา ข้อมูลติดต่อ/LINE จาก Settings มีลูกศรเข้าหน้ารายละเอียดร้าน และเส้นคั่นก่อนแถบสรุป 4 ช่อง (แต้ม / คูปอง / งานที่กำลังทำ / โปรฯ วันนี้) พร้อมไอคอนสีตามภาพ
- เมนูบริการ: การ์ดขาว ไอคอน 5 ช่องต่อแถว 2 แถว ไอคอนอยู่ในกรอบสี่เหลี่ยมมนพื้นอ่อน ป้ายชื่อใต้ไอคอนอ่านง่าย (12–13px)
- แบนเนอร์โปรโมชัน: ใหญ่ขึ้นตามสัดส่วนภาพ มีจุด indicator ใต้แบนเนอร์
- "แนะนำสำหรับคุณ": หัวข้อซ้าย + ลิงก์ "ดูทั้งหมด" ขวา การ์ด 2 คอลัมน์ รูปซ้าย ข้อมูลขวา มีป้ายกำกับสีน้ำเงินใต้ราคา
- ตรวจ responsive iPhone เล็ก/ใหญ่, Android, iPad, desktop และ safe-area ของแถบล่าง

## ส่วนที่ 2 — ระบบจัดการเมนูบริการ (แอดมิน)
เพิ่มแท็บ "เมนูบริการหน้าแรก" ในหน้าตั้งค่าร้าน `/admin/pos-store` ทำได้:
- ลากสลับลำดับไอคอน (drag & drop) บันทึกลำดับอัตโนมัติ
- สวิตช์ซ่อน/แสดงแต่ละเมนู (เมนูที่ซ่อนไม่แสดงฝั่งลูกค้า)
- เพิ่มเมนูใหม่ / แก้ชื่อ / ลบ
- เลือกไอคอนจากชุดไอคอนในระบบ หรืออัปโหลดรูปไอคอนเอง (PNG/JPG/SVG)
- กำหนดปลายทางเมื่อกด: คำค้นสินค้า หรือลิงก์ภายในระบบ
- ปุ่ม "คืนค่าเริ่มต้น" กลับเป็น 10 เมนูเดิม
- ปรับขนาดไอคอน (เล็ก / กลาง / ใหญ่) และจำนวนช่องต่อแถว (4 หรือ 5)
- โหมดแก้ไขแบบเห็นภาพจริง: กดปุ่ม "จัดเรียงไอคอน" แล้วลากไอคอนบนตัวอย่างหน้าแรกได้เลย

ฝั่งลูกค้าอ่านค่าจากฐานข้อมูล ถ้ายังไม่เคยตั้งค่าจะใช้ 10 เมนูเดิมเป็นค่าเริ่มต้น และอัปเดตทันทีเมื่อแอดมินแก้ (realtime)

## รายละเอียดทางเทคนิค
- ตารางใหม่ `shop_service_shortcuts`: `id, key, label, icon_name, icon_url, target_type ('search'|'route'), target_value, sort_order, is_active, created_at, updated_at`
  - GRANT: `SELECT` ให้ `anon`/`authenticated` (เมนูเป็นข้อมูลสาธารณะ), `ALL` ให้ `service_role`; เขียนได้เฉพาะ staff/admin ผ่าน RLS (`is_staff_any()` / `has_role`)
  - seed 10 รายการเดิมจาก `SERVICE_SHORTCUTS`
- รูปไอคอน: อัปโหลดเข้า storage bucket สาธารณะ `shop-icons` (สร้างใหม่) เขียนได้เฉพาะ staff อ่านได้ทุกคน
- โค้ด:
  - `src/hooks/useServiceShortcuts.ts` — ดึงเมนู + realtime + fallback ค่าเริ่มต้น
  - `src/components/shop/home/ServiceShortcuts.tsx` — รองรับ `icon_url` และรายการจาก DB (คง `SERVICE_SHORTCUTS` เดิมไว้เป็นค่าเริ่มต้นเพื่อไม่ให้เทสต์เสีย)
  - `src/components/admin/ServiceShortcutManager.tsx` — UI จัดการ + drag & drop (ใช้ `@dnd-kit` ถ้ามีในโปรเจกต์ ไม่งั้นใช้ปุ่มเลื่อนขึ้น/ลงร่วมกับ drag แบบ HTML5)
  - ปรับ `src/pages/Shop.tsx` เฉพาะส่วนการแสดงผลตามหัวข้อ 1
- ไม่แตะ POS, สต็อก, ตะกร้า, คำสั่งซื้อ, เอกสาร, พนักงาน และไม่เปลี่ยน route เดิม

## ส่วนที่ 3 — bottom nav และ safe-area
- คำนวณความสูงแถบล่างจริง แล้วกำหนด padding-bottom ของเนื้อหาและตำแหน่ง `bottom` ของปุ่มตะกร้าลอยจากค่าเดียวกัน (`--bottom-nav-h` + `env(safe-area-inset-bottom)`)
- บนเดสก์ท็อปที่ไม่มีแถบล่าง ปุ่มตะกร้าลอยจะอยู่มุมขวาล่างโดยไม่ทับเนื้อหา
- ตรวจว่าปุ่มตะกร้าไม่บังแถบล่าง และแถบล่างไม่บังการ์ดใบสุดท้าย ทั้ง iPhone (มี home indicator), Android, iPad, desktop

## ส่วนที่ 4 — หน้าตั้งค่าธีมแบบง่าย
เพิ่มหน้า `/admin/theme` (ลิงก์จากหน้าตั้งค่าร้าน) ให้เลือก:
- โทนสีหลัก (เลือกจากชุดสีสำเร็จ + เลือกสีเองได้)
- สีปุ่ม (accent)
- ความเข้มของไล่เฉดพื้นหลัง (สไลเดอร์ 0–100%)
- แสดงตัวอย่างสดก่อนบันทึก และมีปุ่มคืนค่าเริ่มต้น

เก็บค่าในตาราง `shop_theme_settings` (แถวเดียว) แล้วฉีดเป็น CSS variable ทับ token ใน `src/index.css` ตอนรันไทม์ — ไม่ hardcode สีในคอมโพเนนต์

## การตรวจสอบ
- typecheck + ชุดเทสต์เดิมทั้งหมดต้องผ่าน
- เพิ่มเทสต์: เมนูที่ซ่อนไม่แสดงฝั่งลูกค้า, ลำดับตาม `sort_order`, fallback เมื่อ DB ว่าง
- ตรวจหน้าจอจริงด้วย Playwright ที่ 390px / 768px / 1280px ไม่มีล้นแนวนอน
- ไม่ publish production
