# ผลตรวจ flow ลูกค้า: /shop → ตะกร้า → ส่งคำสั่งซื้อ

ตรวจจริงด้วยเบราว์เซอร์ที่ 375/390px (มือถือ) และ 1280px (พีซี) กับข้อมูลสินค้าจริง พร้อมรันเทสต์ที่เกี่ยวข้อง — ยังไม่แก้โค้ดใดๆ

## 1. ผลการรันเทสต์ — ผ่านทั้งหมด

12 ไฟล์ / 120 เคส ผ่านหมด ไม่มีเคสตก:
customer-shopfront-v2, customer-account, customer-final-polish, mobile-table-ux, mobile-card-mode, mobile-runtime-guards, quotation-first, shop-feature-columns, shop-home-config, myshop-integration, nattapron-v2-redesign, line-order-fail-closed

ข้อสังเกต: เทสต์ `customer-shopfront-v2` เช็คว่ามีคำว่า "ดำเนินการสั่งซื้อ" ในหน้า Cart แต่ปุ่มจริงเขียนว่า "ตรวจสอบก่อนสั่ง" — คำที่เทสต์จับอยู่ในข้อความเตือนบรรทัดล่างเท่านั้น เทสต์จึงผ่านแบบไม่ตรงของจริง (false pass)

## 2. การแสดงผล — ผ่านเกณฑ์หลัก

- ไม่มีการล้นจอแนวนอนทั้งมือถือ (body 360 / viewport 375) และพีซี (1265/1280)
- ไม่มี pageerror และไม่มี HTTP 4xx/5xx ตลอด flow
- การ์ดสินค้า 2 คอลัมน์บนมือถือ อ่านง่าย รูป/ราคา/คงเหลือครบ
- แถบสรุป + ปุ่มสั่งซื้อแบบติดล่างจอบนมือถือทำงานถูกต้อง ไม่ทับ bottom nav

ปัญหาการแสดงผลที่พบ:

1. **ปุ่มลอย 2 ตัวทับการ์ดสินค้าบนมือถือ** — ปุ่ม Layout Tuner (ขวากลาง) บังข้อความ "คงเหลือ" ของการ์ด และปุ่มกลมสีเขียว (ขวาล่าง) ทับการ์ดแถวล่าง
2. **แถวไอคอนบริการบนพีซีกระจายห่างผิดสัดส่วน** — 6 ไอคอนยืดเต็ม 1200px ดูโล่ง ต่างจากบนมือถือที่จัดเป็นกริดสวย
3. **ลิงก์ "นโยบายความเป็นส่วนตัว / เงื่อนไขการใช้งาน" สูงเพียง 16px** — ต่ำกว่าเกณฑ์พื้นที่กดบนมือถือ (แท็บ "ฉัน" ก็สูง 32px)
4. **หน้าร้านโชว์ข้อความ "ยังไม่ได้ตั้งค่า LINE ของร้าน" ให้ลูกค้าเห็น** — เป็นข้อความสำหรับแอดมิน ไม่ควรอยู่หน้าลูกค้า

## 3. ปุ่ม / การทำงานที่มีปัญหา

5. **การ์ดสินค้าไม่มีปุ่ม "เพิ่มลงตะกร้า" ที่มองเห็น** — ต้องแตะทั้งการ์ดถึงจะเพิ่ม (ทดสอบแล้วเพิ่มได้จริง) แต่ลูกค้าไม่มีทางรู้ และการแตะการ์ดก็ไม่เปิดหน้ารายละเอียดสินค้าตามที่คาด
6. **ปุ่ม "แนบไฟล์" ในตะกร้าไม่ส่งไฟล์จริง** — ระบบตรวจไฟล์แล้วโชว์สถานะ "พร้อม" แต่ไฟล์ไม่ถูกอัปโหลดไปไหน ส่งออเดอร์แล้วร้านไม่ได้รับไฟล์ (ในหมายเหตุมีแค่ข้อความว่าแนบแล้ว)
7. **คูปองส่วนลดไม่มีผลกับออเดอร์จริง** — กด "ใช้คูปอง" แล้วยอดบนจอลด แต่ payload ที่ส่งไปเซิร์ฟเวอร์ไม่มีคูปอง/ยอดหลังลด มีแค่บรรทัดข้อความในหมายเหตุ ลูกค้าอาจเข้าใจว่าได้ส่วนลดแล้ว
8. **บังคับกรอก "ที่อยู่" แม้เลือก "รับหน้าร้าน"** — validation ต้องมีที่อยู่ ≥5 ตัวอักษรเสมอ ทั้งที่เลือกรับเองที่ร้าน
9. **การเลือก/ไม่เลือกรายการไม่มีผลกับหัวข้อกลุ่มร้าน** — ตรรกะจัดกลุ่มในตะกร้าเขียนไว้ให้ใช้ "ทุกรายการ" เสมอ (เงื่อนไขที่เขียนไว้เลือกค่าเดิมทั้งสองทาง) รายการที่ติ๊กออกจึงยังโชว์ในกลุ่ม แม้ยอดรวมคำนวณถูก
10. **ข้อความ error ตอนกรอกไม่ครบเด้ง toast แต่หน้าไม่เลื่อนให้เห็นช่องแดงบนมือถือ** — โค้ดมี scrollIntoView แต่จากการทดสอบจริงหน้าจอยังค้างอยู่ที่เดิม ลูกค้าเห็นแค่ข้อความเตือนลอยผ่านไป

## 4. สิ่งที่ทำงานถูกต้อง (ไม่ต้องแตะ)

- เพิ่มสินค้า → ตะกร้าเก็บ snapshot ราคา/หน่วย/รูปครบ ข้ามหน้า/ข้ามแท็บได้
- ปุ่มเพิ่ม-ลดจำนวน, ลบรายการ, เลือกทั้งหมด, ยอดที่เลือก ทำงานถูก
- กด "ตรวจสอบก่อนสั่ง" เมื่อกรอกครบ → ขึ้นแผงเพิ่มเพื่อน LINE ตามนโยบาย gate (ตะกร้าและฟอร์มไม่หาย)
- error จากเซิร์ฟเวอร์ (rate limit, line_required, line_binding_required, idempotency) ถูก handle ครบพร้อมข้อความไทย

## ขั้นถัดไป

รอการอนุมัติว่าจะให้แก้ข้อไหนบ้าง แนะนำลำดับความสำคัญ: ข้อ 6, 7 (ลูกค้าเข้าใจผิดว่าส่งไฟล์/ได้ส่วนลดแล้ว) → ข้อ 5, 8, 10 (อุปสรรคการสั่งซื้อ) → ข้อ 1–4, 9 (การแสดงผล) → ข้อสังเกตเทสต์
