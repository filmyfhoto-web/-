# เปิดแอปทุกอุปกรณ์และตั้งค่าแจ้งเตือน LINE แบบ 2 กลุ่ม

## เป้าหมาย
- เปิดแอปลูกค้า พนักงาน แอดมิน POS, Receipt & Delivery และ Film Shop ได้จากลิงก์กลางเดียวบนมือถือ แท็บเล็ต และคอมพิวเตอร์
- ลิงก์ที่แชร์/คัดลอก/ติดตั้งเป็นเว็บแอปใช้โดเมนหลักและเปิดหน้าเวอร์ชันล่าสุด
- ผูก LINE Group ด้วยคำสั่งในกลุ่มได้ทันที โดยไม่ต้องไปอนุมัติบัญชีพนักงานก่อน
- แยกปลายทางเป็น 2 กลุ่ม: แจ้งเตือนออเดอร์ และรันคิว NATTA.Q

## สิ่งที่จะเปลี่ยน

### 1. ซ่อมหน้าแอปที่เปิดไม่ได้ก่อน
- แก้ `FILM_SHOP_PATH` ที่ถูกเรียกใช้แต่ไม่ได้ประกาศในตัวเลือก manifest ซึ่งเป็นสาเหตุ runtime error ปัจจุบัน
- ตรวจ lazy route/chunk loading และ recovery จาก service worker เพื่อไม่ให้ลิงก์ใหม่เปิดไฟล์ JavaScript รุ่นเก่าแล้วค้าง
- เพิ่ม regression test สำหรับการเลือก manifest ของ Film Shop และการเปิด route หลังอัปเดต

### 2. ทำลิงก์เว็บแอปชุดใหม่ทั้งหมด
- ใช้ `https://filmyynatta.com` เป็นโดเมนหลักสำหรับลิงก์ที่แชร์ออกนอก preview
- เปลี่ยนลิงก์แต่ละ workspace ให้เข้าผ่าน `/launch?app=...` เพื่อเลือก manifest และปลายทางตามสิทธิ์อย่างถูกต้อง
- เพิ่ม/จัดชุดลิงก์ให้ครบ: ลูกค้า, พนักงาน, แอดมิน, POS, Receipt & Delivery และ Film Shop
- ให้ปุ่มเปิด คัดลอก แชร์ และติดตั้งอ้างอิง URL ชุดเดียวกัน ลดลิงก์เก่าหรือเส้นทางที่พาไป workspace ผิด
- ตรวจ manifest, `start_url`, icon และขอบเขตการติดตั้งของแต่ละแอป โดยไม่เปลี่ยน service worker นอกเหนือจากที่จำเป็นต่อการแก้ stale build

### 3. แยก “เข้าแอปพนักงาน” ออกจาก “ผูกกลุ่มแจ้งเตือน”
สถานะจริงตอนนี้มีคำขอ LINE พนักงานค้าง 1 ราย และช่องแจ้งเตือนเดิมเป็นปลายทาง `U...` ซึ่งคือแชทส่วนตัว ไม่ใช่กลุ่ม LINE

- คง `/admin/staff-line` ไว้เฉพาะการให้สิทธิ์ล็อกอินเข้าแอปพนักงาน เพราะเป็นสิทธิ์เข้าถึงข้อมูลและต้องไม่ข้ามการตรวจเจ้าของ
- การผูกกลุ่มแจ้งเตือนไม่อาศัย `staff_line_bindings` และไม่เด้งไปหน้าพนักงานอีก
- ปรับข้อความในหน้า LINE ให้ชัดว่า “อนุมัติพนักงาน” ไม่เกี่ยวกับ “รับแจ้งเตือนในกลุ่ม”

### 4. ผูก LINE ด้วยคำสั่งทันทีแบบ 2 กลุ่ม
- ในกลุ่มแจ้งเตือนออเดอร์: เชิญ OA เข้ากลุ่ม แล้วพิมพ์ `เชื่อมห้องแอดมิน`
- ในกลุ่มรันคิว NATTA.Q: เชิญ OA เข้ากลุ่ม แล้วพิมพ์ `เชื่อมกลุ่มรันคิว`
- ยอมรับคำสั่งเฉพาะ webhook ที่ตรวจลายเซ็นผ่านและ event มาจาก LINE Group จริงเท่านั้น
- เพื่อกันการยึดปลายทาง: ผูกทันทีได้เมื่อประเภทนั้นยังไม่มีกลุ่มจริง หรือมีเพียงปลายทางแชทส่วนตัวเดิม; เมื่อมีกลุ่มผูกแล้ว การเปลี่ยนกลุ่มต้องทำจากหน้าเจ้าของร้าน
- ปิด/แทนที่ปลายทาง `U...` เดิมเมื่อกลุ่มออเดอร์ผูกสำเร็จ และไม่ส่งแจ้งเตือนเข้าบัญชีส่วนตัวอีก
- ตอบยืนยันชื่อกลุ่มและประเภทที่ผูก พร้อมคำสั่งทดสอบที่ตรงกับแต่ละประเภท
- ตั้งกลุ่มที่ผูกสำเร็จเป็นศูนย์รวมของประเภทนั้น เพื่อรวมแจ้งเตือนจากทั้งสองร้านตามตัวเลือก “แยก 2 กลุ่ม”

### 5. ทำหน้าตั้งค่า LINE ให้ใช้งานจบในหน้าเดียว
- แสดงการ์ด 2 กลุ่มพร้อมสถานะสด: ยังไม่ผูก / พร้อมใช้งาน / ทดสอบผ่าน / มีปัญหา
- มีปุ่มคัดลอกคำสั่ง เปิดคู่มือสั้น ทดสอบส่ง และเปลี่ยนกลุ่มสำหรับเจ้าของ
- ซ่อน flow ผู้รับแบบแชทส่วนตัวออกจากส่วนหลัก เพื่อไม่ให้สับสนกับ LINE Group
- แสดงสาเหตุที่ทดสอบไม่ผ่านแบบอ่านง่าย โดยไม่เปิดเผย token/secret

## การทดสอบและยืนยัน
- Unit tests: launch target, manifest selection, canonical/shared links, stale chunk recovery และกติกาผูก/เปลี่ยนกลุ่ม
- Edge function tests: ลายเซ็นไม่ผ่าน, คำสั่งจากแชทส่วนตัว, ผูกกลุ่มแรก, แยก `admin_group`/`queue_group`, ป้องกันกลุ่มอื่นเขียนทับ และคำสั่งทดสอบ
- E2E บนขนาดมือถือ 402×725, แท็บเล็ต และเดสก์ท็อป: เปิดลิงก์ทุกแอป, redirect ตามสิทธิ์, หน้า LINE settings และปุ่มทั้งหมด
- ทดสอบ backend จริงหลัง deploy function: ส่งทดสอบเข้ากลุ่มออเดอร์และกลุ่ม NATTA.Q อย่างละ 1 ข้อความ พร้อมตรวจ delivery log
- รันชุดทดสอบที่เกี่ยวข้อง, build และ security check; เนื่องจากแก้ webhook/auth-adjacent flow จะรัน security scan ซ้ำก่อนสรุปงาน

## ผลลัพธ์ที่ผู้ใช้ทำหลังอัปเดต
1. สร้าง LINE Group 2 กลุ่มและเชิญ LINE OA เข้าทั้งสองกลุ่ม
2. กลุ่มออเดอร์พิมพ์ `เชื่อมห้องแอดมิน`
3. กลุ่ม NATTA.Q พิมพ์ `เชื่อมกลุ่มรันคิว`
4. ระบบตอบยืนยันและเริ่มแจ้งเตือนทันที โดยไม่ต้องหาเมนูอนุมัติพนักงาน
