# ตรวจจับ "รายการสั่งของ" จากข้อความ LINE ธรรมดา

เป้าหมาย: ข้อความแชทที่ลูกค้าพิมพ์มาเป็นรายการ (1. 2. 3. ...) ให้ระบบเดาให้ว่าน่าจะเป็นออเดอร์ แล้วขึ้นการ์ดในหน้า "งานและเอกสาร" ให้กด "สร้างงานจากข้อความนี้" ได้ในคลิกเดียว เหมือนตอนแนบไฟล์

---

## ผลตรวจสอบ 3 ข้อที่สั่งไว้

### 1. ตัวอ่านไฟล์เดิมใช้ได้แค่บางส่วน — ต้องเขียนตัวตรวจจับข้อความเพิ่ม

`excelIntake.ts` ไม่ได้อ่านเอง มันแปลงชีตเป็นข้อความแบบ TSV แล้วส่งต่อให้ `parseSmartImport()` ใน `smartImport.ts` ซึ่งเป็น **parser แบบตาราง**: เดาตัวคั่นจาก tab / จุลภาค / ช่องว่าง 2 ตัวขึ้นไป แล้วอ่านทีละคอลัมน์

ข้อความแชท LINE ไม่มีตัวคั่นแบบนั้น (`1. ฟิวเจอร์บอร์ดขนาดกลาง 20 แผ่น`) — เมื่อส่งเข้า parser เดิม ทั้งบรรทัดจะกลายเป็นเซลล์เดียว ได้ชื่อสินค้าเป็นข้อความยาวทั้งบรรทัด ไม่มีจำนวน ไม่มีราคา และติดธง "ต้องตรวจสอบ" ทุกแถว

สรุป: เขียน **ตัวตรวจจับข้อความใหม่** (ไฟล์ใหม่ `src/lib/chatOrderDetect.ts`) แต่ **ใช้ของเดิมซ้ำ**คือ `cleanNumber()` และรายการคำหน่วยนับ (`UNIT_WORDS`) จาก `smartImport.ts` และส่งผลลัพธ์ออกมาเป็นรูปแบบ `RequisitionItem` เดียวกับที่ "รับงานใหม่" ใช้อยู่ จึงต่อเข้า `saveNewWork()` เดิมได้ทันที ไม่ต้องแตะ parser ไฟล์เลย

### 2. ข้อความ LINE เก็บที่ไหน และเสียบตรงไหน

- ข้อความแชทส่วนตัวจากลูกค้าเข้ามาที่ `supabase/functions/line-webhook` แล้วถูกบันทึกลง `film_conversations` + `film_messages` (`direction = 'inbound'`, ข้อความอยู่คอลัมน์ `text`) ผ่านตัวช่วยกลาง `_shared/inboxStore.ts`
- อีกชุดคือ log ดิบ `line_webhook_events.message_text` (เก็บ 1000 ตัวอักษรแรก) ใช้ตรวจสอบย้อนหลังเท่านั้น
- ตาราง `customer_messages` ที่หน้าแชทของแอดมินใช้ **ไม่ได้มาจาก LINE** — มาจากฟอร์ม "ติดต่อร้าน" บนเว็บ

จุดเสียบที่แนะนำ: **อ่านอย่างเดียวจาก `film_messages` ฝั่งหน้าเว็บ** ไม่แตะ edge function เลย หน้า work-docs ดึงข้อความขาเข้าล่าสุด (เช่น 14 วัน) มาวิเคราะห์ในเบราว์เซอร์ แล้วขึ้นการ์ด — inbox เดิม การแจ้งเตือนกลุ่ม LINE และ flow NATTA.Q ไม่มีอะไรเปลี่ยน เพราะไม่ได้แก้ path ที่รับ webhook

(ทางเลือกที่ไม่เลือกตอนนี้: ตรวจจับใน webhook แล้วเขียนตารางใหม่ — เร็วกว่าเวลาเปิดหน้า แต่ต้องแก้ไฟล์ webhook 2,857 บรรทัดที่คุมงานสำคัญหลายอย่างอยู่ ความเสี่ยงไม่คุ้มในรอบแรก)

### 3. ความแม่นยำที่คาดไว้ (วัดจากข้อความจริงในระบบ)

ข้อความขาเข้าที่เป็นตัวหนังสือทั้งหมด 1,241 ข้อความ มีที่ขึ้นต้นบรรทัดด้วยเลขข้อ 24 ข้อความ (1.9%) — ในจำนวนนี้ 21 ข้อความมีเลขข้อตั้งแต่ 2 บรรทัดขึ้นไป และ 13 ข้อความมีคำหน่วยนับ (แผ่น/แพ็ค/รีม/ชุด ...)

ตัวอย่างจริงที่ **ควรจับ**: `1. กระดาษเคลือบหลังเหลือง a4 2 แพ็ค / 2. ฟิวเจอร์บอร์ดขนาดกลาง 20 แผ่น / ...`

ตัวอย่างจริงที่ **ไม่ควรจับ** (พบในข้อมูลจริง):
- รายชื่อคน: `1.แม่จันสม การินทร์ บุตร / 2.นางนิดดา ...`
- รายการโครงการ+งบ: `1.) 1080 โครงการส่งเสริมความเป็นเลิศ` (เป็นการขอเอกสาร ไม่ใช่รายการสินค้า)

จึงให้คะแนนก่อนแจ้ง ไม่ใช่เจอเลขข้อแล้วเตือนทันที:
- ต้องมีบรรทัดเลขข้อ ≥ 2 บรรทัด
- ≥ 40% ของบรรทัดเลขข้อ ต้องมี "จำนวน + หน่วยนับ" หรือ "ตัวเลขท้ายบรรทัด"
- หักคะแนนเมื่อพบคำบ่งชี้ว่าไม่ใช่รายการของ: `โครงการ`, `งบ`, `บุตร`, `เจ้าภาพ`, `นาย/นาง/นางสาว` นำหน้าบรรทัด
- บวกคะแนนเมื่อมีคำนำ เช่น `รายการ`, `สั่งของ`, `ขอสินค้า`, `รบกวนสั่ง`

คาดผลกับข้อมูลชุดนี้: จับได้ราว 10–14 จาก 24 ข้อความ (แจ้งเตือนราว 1% ของข้อความทั้งหมด) โดยตั้งใจให้ **พลาดไปบ้างดีกว่าเตือนผิดบ่อย** — เคสที่ยังจะพลาด: รายการที่ไม่ใส่จำนวน (`1. ลูกบอลสี`), รายการที่ใช้ - หรือ • แทนเลข (รอบนี้ยังไม่รองรับ), และรายการที่แยกส่งหลายข้อความติดกัน กรณีพลาดยังมีทางออกเดิมคือกด "รับงานใหม่ → พิมพ์รายการเอง"

## สิ่งที่จะทำ

1. **ตัวตรวจจับ** `src/lib/chatOrderDetect.ts` (ใหม่, ไม่แตะฐานข้อมูล): แยกบรรทัด → ตัดหัวเลขข้อ (`1.` `2)` `3.)`) → ดึงชื่อ/จำนวน/หน่วย → ให้คะแนนความมั่นใจ → คืน `{ confidence, items[] }`
2. **ตัวโหลดข้อความ** เพิ่มฟังก์ชันใน `src/lib/workDocs.ts`: อ่าน `film_messages` ขาเข้า 14 วันล่าสุด (จำกัดจำนวน) จับคู่ชื่อ/LINE id จาก `film_conversations` แล้วกรองเฉพาะข้อความที่ผ่านเกณฑ์ และยังไม่ถูกแปลง/ข้าม
3. **การ์ดแจ้งเตือน** ในหน้า `/admin/work-docs` เหนือรายการงาน: "ดูเหมือนเป็นรายการสั่งของจาก [ชื่อลูกค้า] — ตรวจพบ N รายการ" + ปุ่ม **สร้างงานจากข้อความนี้** และ **ข้าม** (ย่อ/ขยายดูข้อความเต็มได้)
4. **สร้างงาน**: กดแล้วเปิด `NewWorkDialog` ที่เติมลูกค้า + รายการมาให้แล้ว (ให้แอดมินตรวจ/แก้ก่อนบันทึกเสมอ ไม่บันทึกเงียบ ๆ) แล้วบันทึกผ่าน `saveNewWork()` เดิม
5. **จำสถานะ "ข้าม"/"แปลงแล้ว"** ด้วยตารางเล็กใหม่ `line_order_hints` (message_id, สถานะ, ใครกด, งานที่สร้าง) พร้อม RLS ให้พนักงานเท่านั้น — เพื่อไม่ให้การ์ดเด้งซ้ำและไม่ให้แอดมินคนละเครื่องเห็นไม่ตรงกัน
6. **เทสต์**: ชุดตัวอย่างข้อความจริง (ควรจับ / ไม่ควรจับ) + เทสต์ว่าการ์ดขึ้นและปุ่มทำงาน

## ความเสี่ยง

- **แจ้งเตือนผิด** — ลดด้วยเกณฑ์คะแนน + ปุ่ม "ข้าม" ที่จำได้ถาวร และการ์ดจะแสดงเฉพาะเมื่อความมั่นใจสูงเท่านั้น
- **ผูกกับตาราง `film_messages`** ซึ่งอยู่ในโมดูล Film Shop ที่เพิ่งแยกออกไป — เป็นการอ่านอย่างเดียว แต่ถ้าอนาคตย้ายตาราง ต้องแก้จุดนี้ตาม (ระบุไว้เป็นคอมเมนต์)
- **ประสิทธิภาพ** — จำกัดช่วงเวลา + จำนวนแถว และตรวจจับเฉพาะตอนเปิดหน้า (ไม่ realtime)
- **ราคาไม่มีในข้อความ** — รายการที่ได้จะไม่มีราคา ต้องไปเติมในขั้น "ยืนยันและแก้ราคา" ที่มีอยู่แล้ว (ราคามาตรฐานเติมอัตโนมัติได้)

**ความซับซ้อน**: ปานกลาง — ตัวตรวจจับ + การ์ด + ตารางเล็ก 1 ตาราง ทำจบได้ในรอบเดียว
