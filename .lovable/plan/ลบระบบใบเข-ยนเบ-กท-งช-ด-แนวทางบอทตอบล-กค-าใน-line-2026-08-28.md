# ลบระบบใบเขียนเบิกทั้งชุด + แนวทางบอทตอบลูกค้าใน LINE

## ส่วนที่ 1 — ลบระบบใบเขียนเบิก

### สิ่งที่ตรวจพบ
- หน้าลูกค้า `/school-requisition` คือหน้าสร้างใบเขียนเบิก และมีทางเข้าจากเมนูลูกค้า, หน้าคู่มือ, แผงบัญชี, ประวัติรวม และปุ่มบนหน้าแรก
- ฝั่งแอดมินไม่มีหน้าใบเบิกแยกแล้ว เส้นทางเก่าถูก redirect เข้า `/admin/work-docs?filter=requisition`; ตัวกรอง "ใบเบิก" ยังอยู่ในหน้า งานและเอกสาร
- โค้ดที่ผูกกับใบเบิกกระจายอยู่ที่ `workDocs.ts`, `workIntake.ts`, `workDocsPricing.ts`, `usePendingWorkCount.ts`, ชุดไฟล์ `requisition*` และหน้าแอดมินเก่า `SchoolRequisitions.tsx` / `RequisitionDesk.tsx`
- ฝั่งเซิร์ฟเวอร์: edge function `school-requisition-notify`, ตัวช่วย `requisitionGroupNotify`, ปุ่ม "ใบเขียนเบิก" ในข้อความต้อนรับหลังเพิ่มเพื่อน LINE และการรองรับชนิด `requisition` ใน `send-work-doc-notify`
- ข้อมูลจริงในระบบตอนนี้: ใบเบิก 2 รายการ (ยังไม่รับทราบทั้งคู่) และ log 2 รายการ ส่วนออเดอร์เว็บมี 13 รายการ

### สิ่งที่จะทำ
1. ฝั่งลูกค้า: ลบหน้า `/school-requisition` และทางเข้าทั้งหมด (เมนูลูกค้า, ปุ่มในหน้าคู่มือ, แผงบัญชี, ประวัติรวม, ปุ่มหน้าแรกในค่าคอนฟิกเว็บ) พร้อมทำเส้นทางเก่าให้พาไปหน้าสั่งซื้อแทน ลิงก์เก่าจะไม่ขึ้นหน้าเสีย
2. ฝั่งแอดมิน: เอาตัวกรอง "ใบเบิก" ออกจากหน้า งานและเอกสาร ให้เหลือคำสั่งซื้ออย่างเดียว, เอาไทล์ "ใบเบิกใหม่" ออกจากหน้าวันนี้, ตัดตัวเลือกใบเบิกในกล่อง "รับงานใหม่" และลบหน้าแอดมินเก่าที่ค้างอยู่
3. ตัวนับ badge งานใหม่และการนับงานวันนี้: เลิกรวมใบเบิก ให้เหลือคำสั่งซื้อเว็บและใบสั่งซื้อลูกค้า
4. LINE: เอาปุ่ม "ใบเขียนเบิก" ออกจากข้อความต้อนรับหลังเพิ่มเพื่อน และตัดเส้นทางแจ้งเตือนที่ใช้เฉพาะใบเบิก
5. Edge functions: ลบ `school-requisition-notify` และตัวช่วยแจ้งกลุ่มเฉพาะใบเบิก แล้วตัดชนิด `requisition` ออกจาก `send-work-doc-notify` พร้อม deploy ฟังก์ชันที่แก้
6. ลบไฟล์ที่ไม่มีใครใช้ต่อ: หน้าและคอมโพเนนต์ใบเบิก, ตัวช่วย `requisitionDesk` / `requisitionLog` / `requisitionPdf` / `schoolRequisition`, สถานะใบเบิก และเทสต์ที่ผูกกับของพวกนี้
7. คู่มือและวิดีโอสอน: เอาหัวข้อ/ตอนที่เกี่ยวกับใบเขียนเบิกออกจากหน้าคู่มือ

### เรื่องฐานข้อมูล
- ค่าเริ่มต้น: ไม่ลบตาราง `school_requisitions` และ `school_requisition_logs` เพื่อกันข้อมูลเดิม 2 รายการหาย แต่แอปจะไม่อ่านและไม่เขียนอีกต่อไป
- ถ้าต้องการล้างตารางทิ้งจริง ๆ บอกได้ จะทำเป็นขั้นตอนแยกหลังยืนยันอีกครั้ง เพราะย้อนกลับไม่ได้

### ความเสี่ยงและการป้องกัน
- ลิงก์เก่าที่ลูกค้าหรือ LINE เคยส่งไว้: กันด้วย redirect ไม่ปล่อยให้ขึ้นหน้าว่าง
- แจ้งเตือนเก่าในระบบที่ชี้ไปหน้าใบเบิก: ปรับปลายทางไปหน้า งานและเอกสาร
- งานใบเบิก 2 รายการที่ยังค้าง: จะหายจากหน้าจอหลังลบ จึงควรตรวจก่อนว่าไม่มีงานที่ยังต้องส่งกลับลูกค้า
- เทสต์เดิมหลายไฟล์อ้างถึงใบเบิก จะตามลบ/ปรับให้ครบและรันชุดเทสต์ให้ผ่าน

## ส่วนที่ 2 — บอทตอบลูกค้าใน LINE

### ของเดิมที่มีอยู่แล้ว
- มี LINE webhook ทำงานจริงอยู่แล้ว รับข้อความและปุ่มกด เก็บข้อความลูกค้าไว้ในระบบ และส่งข้อความกลับได้
- มีการผูกบัญชีลูกค้ากับ LINE, ข้อความต้อนรับหลังเพิ่มเพื่อน, และตัวช่วยเดาว่าข้อความไหนเป็นรายการสั่งของ
- แปลว่าไม่ต้องเริ่มจากศูนย์ เพิ่ม "สมองตอบอัตโนมัติ" เข้าไปในทางเดินเดิมได้เลย

### สิ่งที่แนะนำให้ทำ (เรียงตามความคุ้มค่า)
1. ตอบคำถามซ้ำ ๆ อัตโนมัติ: เวลาเปิด-ปิด, ราคางานยอดนิยม, วิธีสั่ง, ที่ตั้งร้าน — ตอบทันที ไม่ต้องรอพนักงาน
2. เช็กสถานะงานของตัวเอง: ลูกค้าพิมพ์ถามว่า "งานเสร็จยัง" แล้วบอทตอบจากออเดอร์ที่ผูกกับ LINE ของคนนั้น
3. รับรายการสั่งของจากข้อความ: ต่อยอดตัวช่วยเดารายการที่มีอยู่ ให้บอทสรุปรายการที่อ่านได้แล้วถามยืนยันก่อนเข้าระบบ
4. ส่งต่อพนักงานเมื่อเกินความสามารถ: ถ้าบอทไม่มั่นใจหรือลูกค้าขอคุยคน ให้หยุดตอบอัตโนมัติในห้องนั้นและแจ้งพนักงาน

### หลักการที่จะยึด
- บอทตอบเฉพาะห้องแชทลูกค้า ไม่ยุ่งกับกลุ่มภายในร้าน
- เรื่องที่กระทบเงินหรือสถานะงาน ให้ยืนยันก่อนเสมอ ไม่ตัดสินใจแทนลูกค้า
- มีสวิตช์ปิดบอทได้ทันทีทั้งระบบและรายห้อง เผื่อช่วงที่อยากตอบเอง
- ตอบจากข้อมูลจริงในระบบร้าน ไม่เดาราคาหรือสถานะเอง

### สิ่งที่ต้องตัดสินใจก่อนเริ่มทำบอท
- เอาครบทั้ง 4 ข้อ หรือเริ่มจากข้อ 1–2 ก่อน
- โทนการตอบ เช่น สุภาพทางการ หรือเป็นกันเองแบบร้านใกล้บ้าน
- ช่วงเวลาที่ให้บอททำงาน เช่น ตลอดเวลา หรือเฉพาะนอกเวลาทำการ

งานบอทจะเสนอเป็นแผนแยกอีกรอบหลังตอบ 3 ข้อนี้ รอบนี้ลงมือเฉพาะการลบระบบใบเขียนเบิกก่อน

## การตรวจรับ
- ไล่เปิดหน้าลูกค้าและหน้าแอดมินหลัก ตรวจว่าไม่มีเมนู ปุ่ม หรือหน้าใบเบิกหลงเหลือ
- ตรวจว่าเส้นทางเก่าเด้งไปหน้าที่ถูกต้อง ไม่มีหน้าเสีย
- ตรวจว่าหน้า งานและเอกสาร ยังรับงานคำสั่งซื้อ ยืนยันรับ แนบเอกสาร และส่งกลับได้ครบ
- ตรวจว่า badge งานใหม่นับเฉพาะคำสั่งซื้อและยังลดลงเมื่อกดรับทราบ
- รันเทสต์ทั้งหมดและตรวจ build ให้ผ่านก่อนส่งมอบ
