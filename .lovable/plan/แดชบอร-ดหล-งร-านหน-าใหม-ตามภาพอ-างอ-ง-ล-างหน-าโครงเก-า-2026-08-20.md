# แดชบอร์ดหลังร้านหน้าใหม่ (ตามภาพอ้างอิง) + ล้างหน้าโครงเก่า

## เป้าหมาย
ทำหน้าแรกของแอดมิน (`/admin/home` → `/receipts/film`) ให้เหมือนภาพอ้างอิงล่าสุด และเลิกใช้/ลบหน้าแดชบอร์ดโครงเก่าที่ไม่ได้ใช้แล้ว โดยไม่แตะระบบเอกสาร 2 ร้าน, บอทกลุ่ม, LINE backend, POS engine, คิวงาน และ auth

## หน้าใหม่ประกอบด้วย
- Sidebar ม่วงเข้ม: โลโก้ NATTA GROUP (PHOTO · PRINT · DESIGN · SIGN), เมนู 9 รายการตาม `DASHBOARD_NAV`, การ์ดผู้ใช้ + สาขาปัจจุบัน + ปุ่มออกจากระบบด้านล่าง
- Header: ทักทายชื่อผู้ใช้จริง, ตัวเลือกร้าน, วันที่ไทย, นาฬิกาเดินจริง
- Hero banner gradient ม่วง: หัวข้อระบบ + badge "เปิดร้านแล้ว N ร้าน"
- แถวโมดูล 6 ใบ (ออกเอกสาร / POS จอสัมผัส / คิวงาน / สินค้า & สต็อก / ลูกค้า / รายงาน) แต่ละใบมีปุ่ม "เข้าใช้งาน →" ไป route เดิม
- ภาพรวมงานวันนี้ 4 ตัวเลข (รับใหม่ / กำลังดำเนินการ / พร้อมรับงาน / เสร็จวันนี้) ลิงก์ไปหน้ารายการที่กรองแล้ว
- ตาราง "งานล่าสุด" 5 แถว (เลขงาน / ลูกค้า / รายละเอียด / สถานะ / เวลา) กดเปิดออเดอร์จริง
- คอลัมน์ขวา: ยอดขายวันนี้ + กราฟเส้น, ลูกค้ายอดนิยม, ประกาศ/แจ้งเตือน, ลิงก์ด่วน
- ทุกตัวเลขมาจากข้อมูลจริง (WorkcenterProvider / hooks ที่มีอยู่) พร้อม Skeleton และ Empty state ชุด `DataStates` เดิม
- Responsive: 1536 / 1024 (icon rail) / 768 / 390 (hero 2×2, การ์ด 2 คอลัมน์) ตามที่มีอยู่แล้ว

## ล้างหน้าโครงเก่า
- ลบ `src/pages/admin/AdminHome.tsx` (ไม่มีที่ไหนเรียกใช้แล้ว route ชี้มา Film Shop dashboard)
- เปลี่ยน default case ใน `FilmShopApp` ให้ตกมาที่แดชบอร์ดใหม่แทน `dashboard/Dashboard.tsx` เดิม
- `dashboard/Dashboard.tsx` และลูก (`TodayBoard`, `OrderTodayPanel`, `PeriodIncomeCards`, `CategoryHistoryCards`) — ยังผูกกับหน้า "สรุปเอกสาร/ยอดขาย" (`doc-summary`) ถ้าเช็คแล้วไม่มีทางเข้าเหลืออยู่จะลบทิ้งทั้งชุด ถ้ายังมีเมนูเข้าถึงจะเก็บไว้เฉพาะหน้าสรุป แล้วลบเฉพาะส่วน UI ที่ซ้ำกับแดชบอร์ดใหม่
- ลบเทสต์/สแนปช็อตที่อ้างถึงไฟล์ที่ถูกลบ และอัปเดต contract test ของแดชบอร์ด

## ไม่แตะ
เอกสาร 2 ร้าน (`/receipts` templates, VAT, PDF, เลขที่เอกสาร), POS checkout/สต๊อก, คิวงาน/รันงาน, group bot + LINE webhook/backend, auth และ role guards, DB schema

## ตรวจสอบ
`tsgo` + `vite build`, ชุดเทสต์ nav/route registry/dashboard, และเช็คด้วยเบราว์เซอร์ที่ 1536 / 1024 / 768 / 390 ว่าทุกปุ่มพาไป route เดิมได้จริง (ไม่ publish/deploy)
