# เอาหน้า "ใบเขียนเบิก" ฝั่งลูกค้าออก ให้เหลือที่เดียว

## สรุปสถานะปัจจุบัน (ตรวจจากโค้ดแล้ว)
- ฝั่งแอดมิน: `/admin/school-requisitions`, `/admin/requisition-desk` ถูกเปลี่ยนเป็น redirect ไป `/admin/work-docs?filter=requisition` อยู่แล้ว — ใบเบิกดูและจัดการได้ในหน้า "งานและเอกสาร" ที่เดียว
- ฝั่งลูกค้า: ยังมีหน้าแยกอยู่จริงที่ `/school-requisition` (`src/pages/SchoolRequisition.tsx`) พร้อมทางเข้าอีกหลายจุด
- ตะกร้าลูกค้ามีปุ่ม "สั่งซื้อเลย" และ "ขอใบราคา/ใบเบิก" อยู่แล้ว จึงใช้แทนหน้าเดิมได้

## สิ่งที่จะทำ
1. ปิดหน้า `/school-requisition` แล้วทำเป็น redirect ไปตะกร้า (`/cart`) เพื่อไม่ให้ลิงก์เก่าพัง
2. ลบทางเข้าหน้าใบเบิกออกจาก:
   - เมนูลูกค้า (`CustomerLayout`)
   - ปุ่มลัดในหน้าบัญชี (`AccountActionPanel`)
   - หน้าไกด์ (`Guide`)
   - ประวัติรวม (`UnifiedHistory`)
   - รายการเมนู/ปุ่ม CTA ใน `siteConfig`
3. เก็บหน้า/ไฟล์ฝั่งแอดมินและมุมมองใบเบิกใน "งานและเอกสาร" ไว้เหมือนเดิม
4. ไม่ลบตาราง `school_requisitions` และข้อมูลเดิม (2 รายการ) — ยังดูย้อนหลังได้ในงานและเอกสาร

## สิ่งที่จะไม่แตะ
- พฤติกรรมปุ่มในตะกร้า (ยังบันทึกเป็น `orders` + `doc_intent=quote`)
- ไฟล์ auth/session/draft/autosave
- Edge function `school-requisition-notify` และข้อมูลในฐานข้อมูล

## รายละเอียดทางเทคนิค
- `src/App.tsx`: `/school-requisition` → `<Navigate to="/cart" replace />`, ลบ lazy import ที่ไม่ใช้
- `src/lib/siteConfig.ts`: ตัดรายการเมนู `ใบเขียนเบิก` และตั้ง `cta_requisition.enabled = false`
- ลิงก์อื่นๆ ในไฟล์ที่ระบุข้างบนถูกลบทิ้ง (ไม่แก้ logic อื่น)
- อัปเดตเทสต์ที่อ้างลิงก์ลูกค้าเหล่านี้ แล้วรัน targeted tests + build + security check

## ความเสี่ยง
- ต่ำ: เป็นการตัดทางเข้า UI ฝั่งลูกค้าเท่านั้น ข้อมูลและงานฝั่งแอดมินยังครบ
- หากภายหลังอยากได้หน้าเดิมกลับ สามารถเปิด route คืนได้ทันทีเพราะไฟล์ยังอยู่ในโปรเจกต์
