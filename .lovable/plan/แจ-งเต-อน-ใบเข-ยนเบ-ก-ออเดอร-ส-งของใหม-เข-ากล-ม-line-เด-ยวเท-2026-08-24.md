# แจ้งเตือน "ใบเขียนเบิก + ออเดอร์สั่งของใหม่" เข้ากลุ่ม LINE เดียวเท่านั้น

## สิ่งที่ตรวจพบจริงในระบบตอนนี้

กลุ่มปลายทางที่เปิดใช้งาน (ประเภท "กลุ่มรับออเดอร์"):
- 🚀ออเดอร์ขั้นเทพ 🖥 — `C84f36…fedf` (เปิดอยู่)
- อีก 2 กลุ่ม (🤖botรันงาน, bot 🔔แจ้งเตือนออเดอร์) ปิดอยู่แล้ว

ใบเขียนเบิกส่งเข้ากลุ่มนี้อยู่แล้ว (มีรายการส่งจริง เช่น RQ-1C9E1D7D เข้ากลุ่ม 🚀ออเดอร์ขั้นเทพ)

**คนที่ยัง "ได้รับแจ้งเตือนส่วนตัว" (แชท 1:1 กับ OA) — คือสาเหตุที่ยังมีข้อความเด้งหาคน:**
| ป้ายชื่อ | LINE User ID (ปิดบัง) | สถานะ |
|---|---|---|
| FILM | U4f9825…9f07e | เปิด รับแจ้งเตือนออเดอร์ |
| หญิง | U65366e…80670 | เปิด รับแจ้งเตือนออเดอร์ |

นอกจากนี้ยังมีค่า `LINE_ADMIN_USER_ID` ในระบบ ที่ถูกใส่เป็นผู้รับ "เสมอ" แม้จะลบรายชื่อข้างบนออกก็ยังส่งอยู่

ข้อความที่ขึ้นว่า “ผู้รับ: ตรวจสอบโทเคนใหม่ / คุณได้รับข้อความนี้แสดงว่าตั้งค่า User ID ถูกต้อง…” คือข้อความ **ทดสอบผู้รับรายบุคคล** ที่กดจากหน้าตั้งค่า LINE (ใส่ป้ายชื่อว่า "ตรวจสอบโทเคนใหม่") จึงเด้งเข้าแชทส่วนตัวของ 2 ไอดีข้างบน

## จะทำอะไร

1. ตัดการส่งเข้าแชทส่วนตัวทั้งหมดสำหรับ "ออเดอร์สั่งของใหม่" และการเปลี่ยนสถานะออเดอร์ — เหลือส่งเข้ากลุ่มเท่านั้น
2. ทำให้ใบเขียนเบิกและออเดอร์ใช้ "กลุ่มเดียวกัน" อย่างเป็นทางการ (กลุ่มประเภทรับออเดอร์ที่เปิดใช้งาน = 🚀ออเดอร์ขั้นเทพ 🖥) และถ้าเผลอเปิดหลายกลุ่ม ระบบส่งกลุ่มเดียว (กลุ่มล่าสุดที่เปิดใช้งาน) กันข้อความซ้ำ
3. ปิดผู้รับรายบุคคล 2 รายชื่อในฐานข้อมูล และปิดปุ่ม/หน้าจอ "ทดสอบส่งหาผู้รับรายบุคคล" ไม่ให้กดได้อีก เพื่อไม่ให้มีข้อความเด้งหาคนโดยไม่ตั้งใจ
4. ตรวจผลจริง: ส่งใบเขียนเบิกทดสอบ 1 ใบ + ออเดอร์ทดสอบ 1 ใบ แล้วยืนยันว่าเข้ากลุ่ม 1 ข้อความต่อ 1 ใบ และไม่มีข้อความ 1:1 ออกไปเลย

## รายละเอียดทางเทคนิค

- `supabase/functions/guest-order-submit/index.ts`: ลบบล็อกที่รวม `LINE_ADMIN_USER_ID` + `admin_line_recipients` เป็นผู้รับ (เหลือ `notifyOrderGroups`) — ไม่แตะ logic การสร้างออเดอร์/สต๊อก
- `supabase/functions/line-notify/index.ts`: `loadAdminRecipients` / `loadAdminRecipientsForStatus` คืนค่าว่าง (group-only) และปิด kind `test_recipient` (คืน 410 gone); คงเส้นทางแจ้งเตือนถึงลูกค้าไว้ตามเดิม
- `supabase/functions/po-review/index.ts`: `adminRecipients()` เปลี่ยนไปใช้ปลายทางกลุ่มเดียวกัน แทนไอดีส่วนตัว
- `supabase/functions/_shared/orderGroupNotify.ts` + `requisitionGroupNotify.ts`: จำกัดผลลัพธ์ `pickOrderGroupDestinations` ให้เหลือกลุ่มเดียว (กลุ่มที่ `linked_at` ล่าสุด) เพื่อให้ทั้งสองระบบใช้กลุ่มเดียวกันแน่นอน
- Migration: `update admin_line_recipients set enabled=false, notify_orders=false` (เก็บแถวไว้เป็นประวัติ ไม่ลบข้อมูล)
- UI: ซ่อนปุ่มทดสอบ/เพิ่มผู้รับรายบุคคลในหน้า `src/pages/admin/LineRecipients.tsx` และ `LineSettings.tsx` โดยแสดงข้อความว่า "ระบบส่งเข้ากลุ่ม LINE เท่านั้น"
- เทสต์: ปรับ/เพิ่มเคสใน `tests/e2e/order-group-notification.spec.ts` ให้ยืนยัน 1 ปลายทาง 1 ข้อความ และเพิ่มเคสใบเขียนเบิกใช้ปลายทางเดียวกัน แล้วรันชุดเทสต์เต็ม
