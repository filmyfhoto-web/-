# แชร์ลิงก์แล้วลูกค้ายังเห็นหน้าเก่า (หน้า "เข้าสู่ระบบจัดการร้าน")

## ตรวจแล้วพบอะไร

ดึงหน้า `https://filmyynatta.com` สดจากเซิร์ฟเวอร์ (ไม่ผ่านแคช) แล้วพบว่า:

- ไฟล์แอปที่เผยแพร่อยู่คือเวอร์ชันใหม่ — ในบันเดิลมีข้อความของหน้า landing ใหม่ครบ
  (`งานพิมพ์ ที่ใช่`, `NATTA GROUP`, `ดูวิดีโอสอนใช้งาน`)
- ข้อความในภาพ ("เข้าสู่ระบบจัดการร้านนัฐภรณ์ เชียงกลาง / กรุณาเลือกวิธีเข้าใช้งาน")
  **ไม่มีอยู่ในโค้ดปัจจุบันแล้ว และไม่มีในไฟล์ที่เผยแพร่**

แปลว่าเซิร์ฟเวอร์ส่งของใหม่ถูกแล้ว แต่เบราว์เซอร์เครื่องนั้นยังเปิดของเก่าที่ค้างอยู่
สาเหตุคือ Service Worker / PWA cache ของเวอร์ชันเก่า (โปรเจกต์เปิด `vite-plugin-pwa`
โหมด `autoUpdate` ซึ่งอัปเดตให้ก็จริง แต่ต้องปิด-เปิดแท็บก่อน ถึงเห็นของใหม่)

## แก้ทันที (ผู้ใช้ทำเองได้ ไม่ต้องรอโค้ด)

เปิด `filmyynatta.com` แล้วกด Ctrl+Shift+R (มือถือ: ล้างข้อมูลเว็บไซต์ / ปิดแท็บทั้งหมดแล้วเปิดใหม่)
ถ้าหายแปลว่าเป็นแคชตามที่วินิจฉัยไว้จริง

## สิ่งที่จะทำในโค้ด (ให้ลูกค้าไม่ต้องล้างแคชเอง)

### 1. บังคับสลับเวอร์ชันใหม่ทันทีสำหรับหน้า public
- เพิ่ม kill-switch เวอร์ชันใน service worker flow: เมื่อ SW ตัวใหม่พร้อม ให้ `skipWaiting` +
  `clients.claim` แล้ว reload หน้าอัตโนมัติหนึ่งครั้ง (มีตัวกันลูปด้วย session flag)
- ล้าง cache เก่าที่ชื่อไม่ตรงเวอร์ชันปัจจุบันทิ้งตอน activate

### 2. ไม่แคช HTML ของหน้าแรก
- ตั้งกลยุทธ์ให้เอกสาร HTML เป็น network-first (fallback เป็นแคชเฉพาะตอนออฟไลน์)
  เพื่อไม่ให้ app shell เก่าค้างข้ามการเผยแพร่

### 3. ตรวจสอบผลจริง
- รัน Playwright: โหลด `/` ครั้งแรก → ลงทะเบียน SW → จำลองเผยแพร่ใหม่ → ยืนยันว่าหน้าเปลี่ยนเอง
- เช็กว่า PWA ฝั่งหลังบ้าน (admin/pos/staff) ยังติดตั้ง/ทำงานออฟไลน์ได้เหมือนเดิม

## ไฟล์ที่จะแก้
- `vite.config.ts` (workbox runtimeCaching ของ document)
- `src/lib/registerSW.ts`, `src/lib/appUpdate.ts` / `src/lib/autoUpdate.ts` (reload หลังอัปเดต + กันลูป)
- เพิ่มเทสต์ใน `src/__tests__/app-update-cache.test.ts`

ไม่แตะ auth, POS, เอกสาร 2 ร้าน, queue, LINE backend
