# แยกแดชบอร์ดหลักออกจาก FILM SHOP ให้เด็ดขาด

แดชบอร์ด `/admin/home` จะเหลือเนื้อหา NATTA GROUP ล้วน ๆ ส่วนงานของ FILM SHOP เข้าผ่านปุ่มเดียวใน hero

## สิ่งที่จะทำ

### 1. ลบแผง "แจ้งการรับงาน — FILM SHOP" ออกจาก AdminDashboardHome.tsx
ลบทั้งบล็อก: 4 metric tiles (งานรับเข้าวันนี้ / งานด่วน / กำลังผลิต / พร้อมรับ), ป้ายยังไม่อ่าน + ปุ่ม "อ่านทั้งหมดในวันนี้", รายการ `NgFilmIntakeList`, ลิงก์ย่อย (คิวงาน / รับงานใหม่ / ออกเอกสาร) และ empty state
พร้อมกันนั้นลบโค้ดที่ผูกกับมันในไฟล์เดียวกัน: การ query `film_orders`, state `filmJobs / filmRead / filmNew`, `filterFilmRows`, `filmStats`, `filmUnread`, `toggleFilmRead`, `markTodayFilmRead`, helper `filmListTo`, toast "มีงานรับเข้าใหม่" และการเก็บ `seen.film`
ปุ่ม "เปิดพื้นที่ทำงาน FILM SHOP" ใน hero คงไว้เหมือนเดิม (`data-testid="ng-hero-filmshop"`)

### 2. ย้ายลิงก์ "เปลี่ยนรูปโชว์"
รูปโชว์บนแดชบอร์ดมาจาก `site_settings.dashboard_image_url` ซึ่งเป็นค่าตั้งค่าทั่วไปของทั้งระบบ ไม่ใช่ของ Film Shop แต่หน้าจอที่แก้ค่านี้ (`SiteEditorPage`) ถูกวางไว้ในโซน film-shop และ `/admin/site-editor` ปัจจุบันเป็นแค่ redirect ไป `/film-shop/app?p=site-editor`

หน้า `/admin/shop-home` แก้เฉพาะ `shop_theme_settings` (แอปลูกค้า) — ไม่มีส่วนของรูปแดชบอร์ด จึงไม่ใช่ปลายทางที่ถูกต้อง

แนวทาง: เปลี่ยน `/admin/site-editor` จาก redirect เป็นการเรนเดอร์คอมโพเนนต์ `SiteEditorPage` เดิม (ตัวเดียวกัน ไม่แก้ไฟล์ film-shop) ในกรอบแอดมิน แล้วชี้ลิงก์ "เปลี่ยนรูปโชว์" ไป `/admin/site-editor` — ผู้ใช้จะไม่ถูกเด้งเข้าพื้นที่ Film Shop อีก (ตรวจแล้วว่าคอมโพเนนต์นี้ไม่ต้องพึ่ง provider ของ film-shop ใช้เพียง hook ที่อ่าน Supabase ตรง ๆ)

### 3. ตัดตัวกรอง filmStatus
`NgDashboardFilters` ยังใช้กับการ์ด "งานล่าสุด — ออเดอร์สั่งซื้อ" อยู่ (ช่วงวันที่ / สถานะ PO / หน่วยงาน) จึงคงแถบไว้ แต่ตัดเฉพาะ dropdown "งานรับเข้า: ทุกสถานะ" (`ng-filter-film-status`) และ import `filmStatusLabel` ออก
ใน `src/lib/dashboardInbox.ts` เอา field `filmStatus` และฟังก์ชัน `filterFilmRows` ออก (ไม่มีที่อื่นใช้แล้ว) พร้อมทำให้ตัวโหลดค่าจาก localStorage เดิมยังอ่านได้โดยไม่พัง

### 4. ไม่แตะพื้นที่ FILM SHOP
`/film-shop`, `/film-shop/app` และตรรกะ `film_orders` ทั้งหมดคงเดิม 100% — งานรับเข้า/คิวงานยังทำได้ครบที่นั่น

## ผลการตรวจข้อ 5 — หน้าอื่นในโซนแอดมินที่แตะข้อมูล film

ตรวจทั้ง `src/pages/admin`, `src/components`, `src/hooks`, `src/lib` พบ 3 จุด และ **ไม่มีจุดไหนเป็นการเอางาน Film Shop มาโชว์ปนบนหน้าแอดมิน** จึงเสนอว่าไม่ต้องแก้ (รอคำสั่งถ้าต้องการให้แตะ):

- `src/pages/admin/CustomerPurchaseOrders.tsx:392` — `insert` เข้า `film_orders` ตอนแปลงใบสั่งซื้อลูกค้าเป็นงานของร้าน (เป็น business action ไม่ใช่การโชว์แดชบอร์ด)
- `src/pages/admin/LineWebhookEvents.tsx:64,81` — อ่าน `film_job_requests` / `film_orders` เพื่อวินิจฉัย webhook ของ LINE (หน้าเครื่องมือช่าง)
- `src/pages/admin/Settings.tsx:839` — ตัวนับ `film_invoices_filled` ในรายงานสถานะระบบ

## รายละเอียดทางเทคนิค

ไฟล์ที่แก้:
- `src/pages/admin/AdminDashboardHome.tsx` — ลบ query/state/UI ของ film ทั้งหมด
- `src/components/dashboard/ng/NgDashboardFilters.tsx` — ตัด select filmStatus
- `src/lib/dashboardInbox.ts` — ตัด `filmStatus`, `filterFilmRows`, `FILM_READ_KEY`, `seen.film`
- `src/App.tsx` — `/admin/site-editor` เรนเดอร์ `SiteEditorPage` ใน `RequireStaff` แทน `Navigate`
- คงไฟล์ `NgFilmIntakeList.tsx` ไว้ (ไม่ถูกอ้างจากแดชบอร์ดแล้ว) หรือลบทิ้งถ้าไม่มีที่อื่นใช้ — จะลบเมื่อยืนยันว่าไม่มี import เหลือ

เทสต์ที่ต้องอัปเดต/ตรวจ:
- `src/__tests__/dashboard-quick-links.test.ts` (คาดว่า home มี `/film-shop/app?p=group-queue` และ `?p=orders` — ปรับให้เหลือเงื่อนไขปุ่มเดียวใน hero + module card)
- `src/__tests__/dashboard-design-tokens.test.ts`, `src/__tests__/workspace-navigation.test.tsx` — ตรวจว่ายังผ่าน
- เทสต์ของ `dashboardInbox` ถ้ามีอ้าง `filterFilmRows`
- เพิ่มเทสต์ใหม่: แดชบอร์ดหลักต้องไม่มีคำว่า `film_orders` / `NgFilmIntakeList` และต้องยังมีปุ่ม `ng-hero-filmshop`

ปิดท้ายด้วยการรัน test suite ที่เกี่ยวข้อง + ตรวจ build แล้วสรุปผล

## จุดที่ขอการตัดสินใจ

การ์ดโมดูล "FILM SHOP" และ "คิวงาน / ติดตามงาน" ใน `MODULE_CARDS` (แถวไอคอนบนแดชบอร์ด) ยังชี้เข้า Film Shop อยู่ — แผนนี้ **คงไว้** ตามที่โจทย์ระบุว่าลบเฉพาะแผง "แจ้งการรับงาน" บอกได้ถ้าต้องการให้เอาออกด้วย
