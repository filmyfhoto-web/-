# เอาเพดาน 100 รายออกจากหน้ารายชื่อลูกค้า ให้เป็นฐานข้อมูลได้จริง

## สรุปเรื่องลิมิต

ระบบ **ไม่ได้จำกัด** จำนวนลูกค้าที่เชื่อม LINE — ผูกได้ไม่จำกัด ตอนนี้มีบัญชีผู้ใช้ 14 ราย และรายการผูก LINE 257 รายการในฐานข้อมูล

เลข 100 เป็นแค่ "จำนวนแถวที่หน้าจอดึงมาแสดงต่อครั้ง" ที่ฝังไว้ในโค้ดหน้าแอดมิน ซึ่งพอลูกค้าเยอะขึ้นจะทำให้เห็นข้อมูลไม่ครบ จึงควรเปลี่ยนเป็นระบบแบ่งหน้า + ค้นหาจากฐานข้อมูลจริง

## จะทำอะไร

1. **หน้า Customer 360 (ศูนย์ข้อมูลลูกค้า)**
   - รายชื่อลูกค้า: เปลี่ยนจากดึง 300 แถวครั้งเดียว เป็นแบ่งหน้า 50 รายการ/หน้า พร้อมปุ่ม "โหลดเพิ่ม" และแสดงจำนวนลูกค้าทั้งหมด
   - ช่องค้นหา: ค้นจากฐานข้อมูลทั้งหมด (ชื่อ/เบอร์/อีเมล/รหัสลูกค้า/ชื่อ LINE) ไม่ใช่ค้นเฉพาะแถวที่โหลดมาแล้ว
   - รายการ "LINE ที่ยังไม่ผูกลูกค้า": แบ่งหน้าเช่นกัน พร้อมตัวเลขรวม

2. **ประวัติของลูกค้าแต่ละราย** (ออเดอร์ / ใบสั่งซื้อ / ใบเขียนเบิก / ไฟล์ Excel)
   - แสดง 50 รายการล่าสุดก่อน แล้วกด "ดูเพิ่ม" ไปเรื่อย ๆ แทนการตัดที่ 100 เงียบ ๆ

3. **รายชื่อลูกค้าที่ทักเข้ามาทาง LINE OA**
   - แบ่งหน้าแทนลิมิต 100 และแสดงจำนวนรวมของแต่ละร้าน

4. **ประวัติการผูกอัตโนมัติ**
   - แบ่งหน้าแทนลิมิต 100 (ตัวกรองช่วงเวลา/สถานะเดิมคงไว้)

5. **ป้ายบอกสถานะข้อมูล**
   - ทุกตารางเหล่านี้แสดงข้อความแบบ "แสดง 50 จาก 257 รายการ" ให้รู้ชัดว่ายังมีข้อมูลเหลือ ไม่ต้องเดา

ไม่แตะกติกาการผูก LINE, การแจ้งเตือนกลุ่ม, ระบบเอกสาร 2 ร้าน, บอทคิวงาน และ POS engine

## รายละเอียดทางเทคนิค

- ใช้ hook เดิม `src/hooks/usePaginatedList.ts` (มี range paging + count อยู่แล้ว) แทนการ `.limit(100)` แบบ hard-code
- `src/pages/admin/Customer360.tsx`: แทน `profiles ... .limit(300)` และ `line_account_links ... .limit(100)` ด้วย paginated query; ย้ายการค้นหาเป็น server-side ด้วย `or(ilike...)` แบบ debounce 300ms; ประวัติต่อรายเปลี่ยน `.limit(100)` เป็น page size 50 + โหลดเพิ่ม
- `src/film-shop/components/line/LineOaCustomerList.tsx`: `inbox_threads` แบ่งหน้า (คง realtime subscription เดิม รีเฟรชหน้าแรก), `line_store_customers` ดึงเฉพาะ line_user_id ที่อยู่ในหน้าปัจจุบันด้วย `.in()`
- `src/pages/admin/AutoBindHistory.tsx`: `line_login_diagnostics` แบ่งหน้า, ตัวกรองเดิมทำงานร่วมกับ paging
- `select` string ส่งผ่านตัวช่วย `(s: string): string => s` และ pin ชนิดข้อมูลด้วย `.returns<T[]>()` เพื่อไม่ให้ typecheck ช้า
- เทสต์: เพิ่มเคสใน `src/pages/admin/__tests__/` ยืนยันว่าไม่มี `.limit(100)` ค้างในไฟล์เหล่านี้ และหน้าแสดงตัวเลข "แสดง X จาก Y" แล้วรันชุดเทสต์เต็ม
