# แท็บ "ฉัน" เด้งไปหน้า "สินค้า" — สาเหตุจริงและวิธีแก้

## ผลการทดสอบจริง (Playwright บนแอปที่รันอยู่)

- กดแท็บ "สินค้า" → `href=/shop` → URL `/shop` ถูกต้อง
- กดแท็บ "ฉัน" → `href=/my-account` → **URL กลายเป็น `/shop`** และเห็นเนื้อหาหน้าร้าน
- เปิด `/my-account` ตรงๆ → เด้งเป็น `/shop` เช่นกัน
- ไม่ใช่ปัญหา routing, ไม่ใช่ RequireLineLink, ไม่ใช่ cache/build และไม่มี crash

## สาเหตุ (ยืนยันด้วย stack trace ของ history.pushState)

การเปลี่ยนหน้าเกิดจาก effect ใน `src/components/account/MyOrdersPanel.tsx` ซึ่งเป็นคอมโพเนนต์ที่หน้า `/my-account` เรนเดอร์อยู่:

```
บรรทัด 84: if (!session?.guest_id || !session?.phone) { nav("/shop"); return; }
```

เส้นทางของโค้ด: ถ้าไม่มี `id_token` ของ LINE และไม่มี `lineProfile` จะตกไปที่ fallback ของ guest session เดิม เมื่อ guest ยังไม่มี `guest_id`/`phone` (ซึ่งเป็นกรณีปกติหลังจากเราปลดข้อบังคับผูก LINE) โค้ดจะสั่ง `nav("/shop")` ทันทีที่แผงโหลด → ทั้งหน้า `/my-account` จึงถูกดีดออกไปหน้าร้านเสมอ

ผู้ใช้ที่ผูก LINE แล้วจะมี `id_token` จึงไม่โดนเด้ง — ตรงกับอาการที่เจ้าของร้านรายงาน (เห็นหน้าเดียวกันตอนยังไม่ล็อกอิน)

## วิธีแก้ที่เสนอ (แก้จุดเดียว ไม่แตะ routing)

ใน `src/components/account/MyOrdersPanel.tsx`:

1. ลบการ `nav("/shop")` ออกจาก `load()` — คอมโพเนนต์ย่อยไม่ควรพาผู้ใช้ออกจากหน้า
2. แทนที่ด้วยการตั้งสถานะ "ยังไม่มีข้อมูลคำสั่งซื้อ" คือ `setOrders([])` แล้ว `return` เพื่อให้แผงแสดงสถานะว่างตามปกติ (พร้อมข้อความชวนเพิ่มเพื่อน LINE / ไปเลือกสินค้า ซึ่ง UI ว่างมีอยู่แล้ว)
3. ตัด `nav` ออกจาก dependency ของ `useCallback` ถ้าไม่ถูกใช้ที่อื่นในฟังก์ชันนั้น (ปุ่มอื่นๆ ยังใช้ `nav` อยู่ จึงคง `useNavigate` ไว้)

ผลลัพธ์: `/my-account` เปิดได้ทั้งกรณีผูก LINE แล้วและยังไม่ผูก แท็บ "ฉัน" กับ "สินค้า" แยกกันชัดเจน

## การตรวจสอบหลังแก้

- รัน Playwright ซ้ำชุดเดิม: กดแท็บ "สินค้า"/"ฉัน" ทั้งแบบมีและไม่มี session ต้องได้ URL และเนื้อหาคนละหน้า
- รันชุดเทสต์ (`account-routes`, `customer-shopfront-v2`, `nav-4tabs-appmanager`) และเช็ค build

## ความเสี่ยง

ต่ำ — แก้ไฟล์เดียว ไม่กระทบ routing, LINE binding, หรือ logic การโหลดคำสั่งซื้อของผู้ใช้ที่ผูก LINE แล้ว
